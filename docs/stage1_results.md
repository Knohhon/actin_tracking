# Проверка реализации этапа 1

Дата: 17 ноября 2026. Исходные данные не изменялись.

## Найденные свойства данных

- Synthetic train: 20 100 PNG, 670 sequences по 30 кадров, 5 403 931 аннотация.
  Все PNG прочитаны и хэшированы; dangling refs и повторные IDs не обнаружены.
  1 222 track identities содержат внутренние временные пробелы. Все 100 масок
  детерминированной decode-выборки имеют расхождение bbox; area совпадает.

- Основной real: 342 записи, 22 754 аннотации, 120 физических PNG,
  114 перекрывающихся окон. Конфликтов GT между повторами PNG не найдено.
- Альтернативный real: 117 PNG и 7 783 аннотации. Общая GT совпадает с основным
  источником; отсутствуют 139.png, 239.png, 339.png. Это не независимый split.
- Synthetic val: 300 кадров, 10 sequences, 79 735 аннотаций. Порядок 0..29
  восстанавливается числовой сортировкой. У 17 track identities есть временные
  пробелы; это диагностика, а не автоматическое признание GT ошибочным.
- В полном decode real (22 754 + 7 783 масок) и synthetic val (79 735 масок)
  не найдены ошибки RLE и расхождения area. Bbox каждой проверенной маски
  отличается от COCO bbox. Например, source [270,341,32,48] против decoded
  [270,341,33,49]. Вероятная причина — соглашение об учёте граничного пикселя;
  исходники не исправлялись, преобразование требует отдельной версии данных.
- FPS, µm/px, provenance калибровки и непрерывность реальных диапазонов
  в просмотренных metadata и исходном README не установлены. Они остаются null.

## Проверки кода

23 теста: fixtures COCO/RLE, точные ID >2^53, порядок, windows/dedup/conflicts,
повреждённые refs/PNG/JSON, треки, чтение SQLite, CLI и dry-run. Ruff и mypy проходят.
pycocotools 2.0.8 с NumPy 2.2.6 выдаёт DeprecationWarning при decode;
проверки RLE roundtrip и геометрии проходят.

Импорт train выполнялся потоково. После чтения JSON заключительные проверки
были продолжены из SQLite после оптимизации covering indexes; повторно
загружать JSON в память не потребовалось. Числовой peak RSS заключительного
процесса не следует интерпретировать как измерение peak RSS первоначального импорта.

Большой кэш находится на Linux-диске WSL: на диске C: недостаточно свободного
места. Путь из outputs ведёт к временному каталогу /tmp, который не является
долговременным хранилищем. Индекс можно воспроизвести командой audit.


Полные локальные артефакты: `outputs/stage1_audit/` → `/tmp/actin-stage1-final/`.
Исходный train JSON SHA256:
`ce63d1817fe100d11f155dd8f1f7096374392506ba1aa5ca90a03b0eccf97115`.
Коммитируемый компактный manifest: `docs/dataset_manifest.v0.2.1.json`.


Между train и val не обнаружены общие sequence IDs, annotation IDs или
полностью совпадающие PNG content hashes. Это не доказывает отсутствие
латентно связанных генераций: их provenance в исходниках недостаточен.
Три неиспользованных PNG альтернативной real-разметки отмечены как
unreferenced_png; основной real источник использует все 120 кадров.

В итоговом основном проходе декодировалась выборка 100 масок каждого источника;
полные decode-проверки val/real выполнены отдельно, как описано выше.
Исходный потоковый импорт train завершён без OOM. Завершающий процесс с
валидацией кэша и val/real использовал peak RSS 108376 KiB (~106 MiB);
это не измерение peak RSS предыдущей фазы импорта.
