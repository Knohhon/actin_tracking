# Аудит и индекс данных

`actin audit --config configs/datasets/v0.2.1.toml --output outputs/audit_v021`
потоково импортирует все четыре исходных COCO JSON: synthetic train/val,
основной real и альтернативный real (последний — вспомогательный, не новый split).
`--subset` ограничивает поднабор, `--mask-sample N` задаёт размер выборки для
декодирования, `--full-masks` декодирует все структурно валидные маски.
Повторное использование выходного каталога запрещено. Неуспешный импорт
оставляет частичный индекс без summary, непригодный для DatasetIndex.

## Проверки

- Один `ijson.parse` проход, SHA256 исходного JSON во время чтения.
- Exact integer/string IDs, SQLite TEXT keys; invalid/dangling refs и повторные
  IDs сохраняются как issues. Некорректные записи не чинятся; валидные payload
  сохраняются вместе с геометрией исходника. Отклонённые записи имеют описание
  ошибки и ID в issues, полный оригинал остаётся в неизменяемом source JSON.
- Категории, bbox/area, RLE dimensions и покрытие compressed/uncompressed runs
  проверяются для всех объектов. Декодирование выполняет pycocotools; выборка
  по сортировке SHA256(annotation ID), воспроизводима без RNG. Для защиты
  от ошибочных размеров decoder ограничен 64 млн пикселей на маску.
- Маски и boxes сравниваются с исходной геометрией без tolerance в целый пиксель:
  несовпадения inclusive/exclusive bbox видны в отчёте, а не скрываются.
- Дубликаты масок и GT-повторы сравниваются по точному представлению RLE.
  Разные, но эквивалентные RLE-кодировки могут потребовать отдельной проверки.
- Синтетические sequences сортируются по числовому суффиксу, проверяется 0..29,
  одна identity на кадр, отсутствие внутренних временных пробелов track ID.
  Разрыв identity — диагностическое замечание, не доказательство ошибки GT.
- PNG: существование, безопасный путь, сигнатура/размеры в заголовке, полный
  SHA256 bytes. Это не полная проверка декомпрессии всех PNG; декодируется
  детерминированная brightness-выборка до 100 кадров.
- Для real сравниваются annotation multisets по физическому PNG, игнорируя
  source-local image/annotation ID. При равенстве каноническая запись — первая
  в исходном JSON. При конфликте frame исключён из iter_unique_frames.
- Между train/val проверяются sequence IDs, annotation IDs и SHA256 PNG.
  Это не доказывает независимость разных генераций одной латентной траектории:
  происхождение генерации в исходных данных недостаточно описано.

## Артефакты и ограничения

SQLite содержит `images`, `annotations`, `physical_frames`, `categories`, `issues`,
`metadata`; индексы по sequence/frame, annotation/image ID. JSON читается один
раз, последующее чтение по ID не обращается к исходному COCO.

Manifest содержит checksums JSON и агрегат content hashes PNG, исходные info и
licenses, статистику и ограничения; подробный mapping PNG→SHA256 находится в
physical_frames. `.sqlite` и outputs не коммитятся. Скрипт не распространяет данные.
В локальных metadata указан CC BY-NC-SA 2.0; внешняя юридическая проверка не проводилась.

Отчёт показывает instances/frame, density, bbox/area histograms, track lengths
в кадрах и brightness frame means. На выборке масок также считается число
пикселей Zhang–Suen skeleton; на трёх уникальных кадрах — количество пар масок
с положительным IoU. Это диагностические proxies, не физическая длина и не
число пересечений осевых линий. Статистика по исходным records; real окна
повторяют физические PNG. Точные arc lengths и пересечения осевых линий
относятся к measurements следующих этапов; диагностические proxies
не используются вместо GT этих величин.

В README набора и просмотренных metadata не подтверждены FPS, µm/px и
непрерывность реальных диапазонов. Поля calibration остаются null,
tracking evaluation real не разрешается. Из metadata не выводится калибровка
по догадкам. Полный decode контроль — отдельный затратный запуск.

См. [локальный результат проверки](stage1_results.md).

Дополнительные diagnostics: на первых `--mask-sample` декодированных масках
считается число пикселей после Zhang–Suen thinning (в полном проходе размер
этой выборки также ограничен `--mask-sample`). Это не arc length и не GT
benchmark длины. На трёх физических кадрах с наименьшими SHA256 имён считаются
пары масок с положительным IoU; при >2048 instances кадр пропускается с причиной.
Этот показатель описывает overlap, а не геометрическое пересечение осевых линий.

README исходного набора и metadata не задают FPS, µm/px или подтверждение
непрерывности real. Значения остаются null; наличие последовательных имён
не считается доказательством непрерывной съемки.


PNG IO использует 8 потоков и пакеты по 32 файла; полный список futures в память
не создаётся. SQLite изменяет только основной поток. Порядок агрегации hashes
сохраняется по file_name независимо от порядка завершения потоков. Прогресс
файлов фиксируется пакетами; metadata summary появляется только после полного
завершения. Покрывающие индексы масок и identities включают annotation ID,
чтобы GROUP BY не читал случайные страницы большой таблицы для каждой записи.
